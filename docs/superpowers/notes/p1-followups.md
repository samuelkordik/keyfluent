# P1 follow-ups for later phases (from P1 reviews, 2026-11-25)

## Rulings made during P1 (controller)
- Ruling 1: tokenizer — a standalone `\;` token (as `list-keys` prints it) separates commands within a binding; `;` inside quotes is literal; `{ … }` blocks are kept as one token and parsed as a nested command list where a command expects one — matches tmux's own syntax — cost if wrong: a few stock bindings parse to the wrong command (caught by the stock test).
- Ruling 2: `pub struct PromptRequest { pub prompt: String, pub initial: String, pub template: Vec<CommandLine> }` in kf-tmux commands.rs (`initial` from `-I` with `#W`/`#S` already expanded; template substituted with `%%`) — the plan names the variant but not the type — cost if wrong: a rename in T6.
- Ruling 3: fixtures — `two-panes-h` (active = right, as after a split), `two-panes-h-first` (active = left), `two-panes-v` (active = bottom), `two-panes-v-first` (active = top), `four-panes` (2×2, active = bottom-right, last_active = top-left), plus `one-pane`, `three-windows` (current 1, last 0) — T7 cards need a reachable move in each direction and a `last_active` — cost if wrong: fixture tweaks in T7.
- Ruling 4: `window-rename` uses `one-pane` (window `0:bash`), goal `window_name = "logs"` — no override mechanism exists and the plan's intent is "a window not yet named logs" — cost if wrong: none.
- Ruling 5: `pack::canonical_keys(card: &Card<Goal>) -> Vec<Key>` (no tables param); recomputing keys from custom tables is P5 — YAGNI — cost if wrong: one added parameter in P5.
- Ruling 6: T2 removes `pub use kf_core::VERSION` from kf-tmux (real API arrives); `use kf_tmux as _;` in kf-app stays until P3 uses kf-tmux — cost: none.
- Ruling 7: list-keys parsing skips mouse-key bindings (names starting Mouse, Wheel, DoubleClick, TripleClick, SecondClick, incl. with M-/C-/S- prefixes) silently — counted in a `skipped_mouse: usize`, not warnings — the simulator is keyboard-only and Task 2's test demands zero warnings on the stock file — cost if wrong: mouse bindings invisible to the app (intended).
- Ruling 8: Task 2 tokenizer unescapes `\x` → `x` and strips surrounding quotes in key tokens before `Key::from_str` (stock prints `\"`, `\#`, `\;`, `\{`, `\}`, `\~`, `\$`, `"M-{"`) — cost if wrong: a few stock keys unparsed (caught by the zero-warnings test).
- Ruling 9 (Task 5): select-pane wrap-around — add `layout::neighbour_wrapping(layout, area, from, dir)` reusing neighbour's search from the opposite edge (tmux does this in window_pane_find_*) — avoids duplicating adjacency in commands.rs — cost if wrong: none.
- Ruling 10 (Task 5): split-window nests a new 2-child split in place of the target pane (tmux halves the target: 80 → 40|39, then -h on right → 40|19|19); `-b` not needed — matches tmux — cost if wrong: layouts differ slightly from tmux after 3+ splits.
- Ruling 11 (Task 5/6): `Server::message` is the single source: commands set it; `Tmux::key` clears it on the next key press (tmux shows a message until a key or timeout); `Overlay.message` is filled from it by `Tmux::grid` — cost if wrong: none.
- Ruling 12 (Task 7): add serde (derive) to kf-tmux and `Deserialize` on `SplitDir` (`"h"`/`"v"` lowercase) for `Goal`.
- Ruling 13: the simulated tmux is a fixed 80×24 model (PANE_AREA 80×23 + status). Task 6's `Tmux::grid(cols, rows)` renders that model; the app (P3) scales the 80×24 grid to the window rather than resizing tmux. A real `Server.area` is P4+ if ever needed — cost if wrong: one field + parameter later.
- Ruling 14: a confirm-before answer (`y`/`n`) returns text_entry=false — the canonical routes write `y` inside a Keys step, so Card::binding_key_count counts it; the grader must count it the same way (spec §6.4 lists the confirm `y` as a step). Typed text exempt = prompt input, command prompt, search, shell only — cost if wrong: budget off by one key on kill cards.
- Ruling 15 (Task 7, from implementer concern): a card must not be solvable by a *different* single binding — otherwise the learner can pass `pane-last` with `o` and never learn `;` (anti-goal: unfair/useless grading). Fixtures change: `four-panes` last_active = top-right (so `;`→TR, `o`→TL, arrows→TR/BL; pane-next goal TL unique); new `four-panes-row` (4 panes side by side, active 0, last_active 2) for pane-last (`;`→2, `o`/Right→1, Left wraps→3); new `five-windows` (0 bash,1 logs,2 editor,3 notes,4 build; current 2, last 0) for window-last (→0; n→3, p→1) and window-select "Go to window 4"; three-windows keeps next/prev (→2 / →0). New content test: for each single-binding card, every other stock `prefix` binding applied once from the start state must not meet the goal (explicit allowlist for true aliases, if any) — supersedes Ruling 3's four-panes last_active — cost if wrong: fixture churn.
- Ruling 16: number keys (`select-window -t :=N`) are allowlisted for window-next/prev/last in no_other_single_binding_solves_a_card, with a comment — a number key is a legitimate alternative route that needs reading the status bar; renumbering windows ≥10 would confuse beginners. P2 follow-up: when a correct route ran a different binding than the canonical one, grade at most Good and show "This card practices `C-b n`" — cost if wrong: learners can pass those three cards with number keys until P2.
- Ruling 17: inside an input prompt, only inserted characters (printable chars, Space) are text_entry=true; editing/submit/cancel keys (C-u, BSpace, Enter, Escape, C-c) are binding keys (text_entry=false) — matches Card::binding_key_count (canonical routes put them in Keys steps) — cost if wrong: budget leniency differs by 1–2 keys on rename cards.
