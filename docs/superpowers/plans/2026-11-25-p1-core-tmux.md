# P1 Core + tmux Simulator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pure-logic crates that parse tmux key notation and `list-keys` output, simulate tmux panes, windows and prompts from real key tables, render a cell grid, and ship the Basics cards. A test proves every card's canonical keys reach its goal.

**Architecture:** `kf-core` holds pack-agnostic pieces (keys, key tables, cell grid, card model). `kf-tmux` holds the tmux model: keys are looked up in key tables and run as **tmux commands** against the state, so custom tables only swap the lookup (spec §6.1, §6.7). No UI code in either crate.

**Tech Stack:** Rust, `serde` + `toml` (cards), `thiserror` (typed errors). No other runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-25-keyfluent-design.md` (§5, §6.1, §6.3, §6.7, §7)

## Global Constraints

- No panics on any input: key strings, `list-keys` text and card TOML are untrusted. Typed errors (`thiserror`).
- Cards are tied to commands and goals, never to keys. Canonical keys are data, checked against the stock tables.
- Stock tables: **tmux 3.4** `list-keys`. Basics curriculum uses only bindings identical in 3.0a–3.5. No `M-` cards.
- Default terminal size for fixtures: 80 columns × 24 rows (23 for panes + 1 status line).
- Copy mode, sessions/detach/shell, choose-tree, display-panes and layouts are **P4**. Their commands return `CmdError::NotSimulated` here.

## Review Focus

1. **Unbound key after the prefix** (e.g. `C-b` then `k`): tmux does nothing and clears the prefix. Expect no state change, `prefix_pending == false`.
2. **Prefix twice** (`C-b C-b`): stock binding is `send-prefix`; expect no state change and no error (the fake pane has no program to receive it).
3. **Closing the last pane of the last window**: session ends; the simulator must not panic. Expect `Tmux::client().attached == None` (the detached shell itself arrives in P4).
4. **Splitting a pane that is too small**: tmux shows "no space for new pane"; expect the message on the status line and an unchanged layout after ~10 splits of an 80×23 area.
5. **Rename prompt cancelled or emptied**: `Escape` leaves the name unchanged; `Enter` on an empty prompt leaves it unchanged too (tmux ignores an empty rename).

### Task 6: Key dispatch and prompts

**Files:**
- Create: `crates/kf-tmux/src/sim.rs`, `crates/kf-tmux/src/prompt.rs`

**Interfaces:**
- Consumes: `KeyTables`, `run`, `Effect`, `render`.
- Produces:
  - `pub struct Tmux` with `Tmux::new(server: Server, tables: KeyTables) -> Tmux`, `key(&mut self, k: &Key) -> KeyOutcome`, `grid(&self, cols: u16, rows: u16) -> CellGrid`, `server(&self) -> &Server`, `prefix_pending(&self) -> bool`, `in_text_entry(&self) -> bool`.
  - In `kf-core` (add to `lib.rs`): `pub struct KeyOutcome { pub text_entry: bool }`. `text_entry` is true when the key was typed into an open prompt, used by the P2 failure budget (spec §6.4).
  - Prompt behaviour: `command-prompt -I '#W' "rename-window -- '%%'"` opens with the current window name pre-filled; printable keys insert, `BSpace` deletes, `C-u` clears, `Enter` substitutes `%%` and runs, `Escape`/`C-c` cancels. The `:` prompt runs the typed text as a command line (tokenised as in Task 2; errors become `server.message`, e.g. `unknown command: foo`). Confirm prompts: `y` runs `then`, any other key cancels.
  - Dispatch: if a prompt is open, the key goes to it. Otherwise, if the prefix is pending, look up `prefix`; else look up `root`, and the prefix key (from the `root`/`prefix` relationship: the key bound to `send-prefix` in `prefix` is the prefix, normally `C-b`) sets `prefix_pending`. Unbound keys after the prefix clear it (Review Focus 1). `-r` repeat bindings: after a repeatable binding, further repeatable keys within 500 ms run without the prefix (time passed in via `key_at(&mut self, k, now: Duration)`; `key` uses the last time).
